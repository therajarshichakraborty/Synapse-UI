There are two ways to install components. Both read the same registry, write the same files to the same folders, and need a project that **already uses shadcn/ui**. Neither one scaffolds a new app.

| Kind                     | Installed to             |
| ------------------------ | ------------------------ |
| React components, blocks | `components/synapse-ui/` |
| React Native components  | `components/native/`     |
| Hooks                    | `hooks/`                 |

Folders follow your `components.json` aliases and `tsconfig` paths, including `src/`.

## Before you start

Set up shadcn once, if you have not already:

<PmCommand dlx="shadcn@latest init" />

## Synapse CLI

The CLI is published on npm as [`synapse-ui-cli`](https://www.npmjs.com/package/synapse-ui-cli). Run it with your package runner (always the latest version), or install it:

```bash
npm i -D synapse-ui-cli      # per project, then: npx synapse-ui-cli add button
npm i -g synapse-ui-cli      # globally, then:    synapse-ui-cli add button
```

### init

Adds the Synapse design tokens to the stylesheet named in `components.json`. Run it once per project.

<PmCommand dlx="synapse-ui-cli@latest init" />

### add

Adds components and everything they depend on. For example, `dialog` also adds `button`, and `native-fab` adds the shared native `icon` and `theme` files. Missing npm packages are installed with your package manager (`npx expo install` in Expo apps).

<PmCommand dlx="synapse-ui-cli@latest add dialog native-fab" />

### Add everything

Add every component in one command. Without a flag, the CLI reads your `package.json`: Expo and React Native apps get every native component, and every other React app gets every React component and block.

<PmCommand dlx="synapse-ui-cli@latest add --all" />

Only the React components and blocks, never the native ones (installed to `components/synapse-ui/`):

<PmCommand dlx="synapse-ui-cli@latest add --all --react" />

Only the React Native components, never the web ones (installed to `components/native/`):

<PmCommand dlx="synapse-ui-cli@latest add --all --native" />

Every React **and** every React Native component, for monorepos or apps that ship both:

<PmCommand dlx="synapse-ui-cli@latest add --all --both" />

| Command              | React (web) | React Native |
| -------------------- | :---------: | :----------: |
| `add --all`          |  detected   |   detected   |
| `add --all --react`  |     Yes     |      No      |
| `add --all --native` |     No      |     Yes      |
| `add --all --both`   |     Yes     |     Yes      |

The flags also apply to names. In a React Native project, `add button select` installs `native-button` and `native-select`; `add button --react` installs the React (web) button instead.

| Option             | Description                                                                 |
| ------------------ | --------------------------------------------------------------------------- |
| `-a, --all`        | Every component for this project (React or React Native, auto-detected)     |
| `--react`          | Only React (web) components and blocks. Alias: `--web`                      |
| `--native`         | Only React Native components. Alias: `--rn`                                 |
| `--both`           | React and React Native together                                             |
| `-o, --overwrite`  | Replace files that already exist                                            |
| `-y, --yes`        | Skip confirmation prompts                                                   |
| `--dry-run`        | Show what would change without writing anything                             |
| `--cwd <path>`     | Run in a different directory                                                |
| `--registry <url>` | Use a self-hosted registry (default: `https://synapse-ui-dev.vercel.app/r`) |

### list

Prints every item, grouped by where it installs. Add `--react` or `--native` to show one platform.

<PmCommand dlx="synapse-ui-cli@latest list" />

<PmCommand dlx="synapse-ui-cli@latest list --native" />

## shadcn CLI

Every item is a standard shadcn registry item, so the shadcn CLI installs it to the same folders:

<PmCommand dlx="shadcn@latest add https://synapse-ui-dev.vercel.app/r/native-fab.json" />

Everything at once. `all.json` holds every React component and block, `all-native.json` every React Native component:

<PmCommand dlx="shadcn@latest add https://synapse-ui-dev.vercel.app/r/all.json" />

<PmCommand dlx="shadcn@latest add https://synapse-ui-dev.vercel.app/r/all-native.json" />

Or register Synapse as a namespace in `components.json` and use short names:

```json title="components.json"
{
  "registries": {
    "@synapse": "https://synapse-ui-dev.vercel.app/r/{name}.json"
  }
}
```

<PmCommand dlx="shadcn@latest add @synapse/dialog @synapse/native-fab" />

## Registry format

Each item is served at `/r/<name>.json` and follows the [shadcn registry schema](https://ui.shadcn.com/docs/registry). Files carry an explicit `target`, and dependencies on other Synapse items are full URLs, so the shadcn CLI never swaps in its own components.

```json title="/r/dialog.json"
{
  "name": "dialog",
  "type": "registry:component",
  "dependencies": ["lucide-react", "radix-ui"],
  "registryDependencies": ["https://synapse-ui-dev.vercel.app/r/button.json"],
  "files": [
    {
      "path": "components/synapse-ui/dialog.tsx",
      "target": "components/synapse-ui/dialog.tsx",
      "type": "registry:component",
      "content": "..."
    }
  ]
}
```
